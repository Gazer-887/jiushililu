## 二、三条容易踩的坑（都来自官方文档明文）

### 坑一：套餐和按量的地址**不能混用**

**智谱官方原话**：

> 「**错误配置端点将导致无法使用 GLM Coding Plan 套餐额度**」
> 「Coding 端点仅限 Coding 场景，与通用端点**不可互相替代**，也不会互相消耗额度」

也就是说：**你买了套餐，却填了通用地址 → 套餐额度用不上，会去扣你的余额**。

**智谱还有一个更隐蔽的坑**（官方明文）：

> 「只有**从未购买过** Coding Plan 的账号，走 Anthropic 接口时才会消耗余额；
> 只要买过套餐（无论是否用完、是否到期），该接口都**不会走余额**，需要额外加白处理。」

意即：**买过套餐的账号，之后想切回按量，用 `…/api/anthropic` 这条路会走不通。**
切回按量请用 `https://open.bigmodel.cn/api/paas/v4`。

### 坑二：计费方式可能**藏在 API Key 里**，不只是地址

**小米 MiMo**：按量 Key 以 `sk-` 开头，Token Plan 套餐 Key 以 `tp-` 开头 ——
**Key 类型和地址必须配套**。

**MiniMax 官方原话**：

> 「**计费方式由你使用的 API Key 决定**。不同类型的 key 会触发不同的计费方式。」

**⇒ 拿错 Key 的表现是"报错"，而不是"提示你用错了"** —— 如果遇到莫名其妙的鉴权失败，
**先回头确认：这个 Key 是哪一档的？和这个地址配套吗？**

### 坑三：地址形态五花八门，**`/v1` 不是通用惯例**

| 厂商 | 地址形态 |
|---|---|
| DeepSeek | `https://api.deepseek.com`（**可以不带 /v1**，官方说 `/v1` 与模型版本无关） |
| Kimi 开放平台 | `…/v1` |
| 通义千问 | `…/compatible-mode/v1`（**带中缀**） |
| **智谱** | `…/api/paas/**v4**`（**是 v4 不是 v1**） |
| **火山方舟** | `…/api/**v3**`（**是 v3 不是 v1**） |

| 小米 Token Plan | `https://token-plan-cn.xiaomimimo.com/v1`（**独立域名**） |

**⇒ 照抄厂商文档给的完整地址**，不要自己"补一个 /v1"或"去掉一个 /v1"。
（应用内已在修复这个拼接问题；但**照抄官方原文永远是最稳的**。）

## 三、关于"获取可用模型"功能

设置页的**「获取可用模型」**会去问厂商"这个地址下有哪些模型"，然后让你勾选导入。
它的前置条件只有三个：**协议对、地址对、Key 对**。

| 情况 | 表现 |
|---|---|
| 该厂商提供模型列表接口 | 列出模型，勾选即导入（省得手抄模型名） |
| 该厂商**不提供**模型列表 | 会明确告诉你「此端点不提供模型列表」，请手填模型 ID |
| Key 无效 / 类型不对 | 会提示鉴权失败 —— **结合坑二检查 Key 类型** |

> **已知**：硅基流动（`https://api.siliconflow.cn/v1`）等聚合平台、以及各类中转站
> （one-api / new-api 自建等）**都可以用自定义方式接入** —— 它们大多提供模型列表接口，
> 用法与上表厂商完全一致。国外厂商（OpenAI / Anthropic / Gemini 等）同理，走自定义。

## 五、本文的来历

本文数据来自 2026-09-17 的一次**方案探路**。当时的设想是"做几个厂家的快速接入（选厂家 → 自动填地址）"，
探路过程中把上面这些地址逐个查证了一遍，也挖出了"套餐/按量不可混用""计费可能藏在 Key 里"这些坑。

**该方案随后被废弃**（依据项目「懒人原则」：预置配置要长期跟进厂商变更，维护成本不划算）。
**但查证结果本身是有价值的** —— 于是把"要我们维护的预设数据"换成"你可以随时对照的文档"。

一个副产品：这次探路还顺带发现了应用内 URL 拼接的一个缺陷（把 `/v1` 写死当版本段，
导致智谱这类 `/v4`、火山方舟这类 `/v3` 的地址会被拼错）—— 该缺陷已立为修复项（`PLAN/plan47_模型自接入改进.md`）。
