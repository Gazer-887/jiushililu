# 对话内预览：当前源码能力与边界

## 当前状态

对话内预览已提交到源码（2026-10-25），随主线集成提供。已发布的 v0.13.110 安装包不含本节源码增量；安装包版本与下载以[GitHub Releases](https://github.com/Gazer-887/jiushililu/releases)为准。本说明描述能力与边界，不替代目标提交的测试结果。

## 已在真实应用检查过的入口

输入区的文件卡可打开文档；发送后绑定稳定消息身份，修改原文件、重启应用仍读取发送时副本。宿主校验消息实际引用，而非只校验会话或资产“存在”。临时草稿由宿主签发并绑定窗口，保存成功后转为历史；本地身份、资产路径和文档引用不进入模型请求体。

PDF由可信组件、本地pdfjs worker和浏览器canvas绘制真实页面，支持翻页、缩放、键盘导航及无文本层扫描图像。用户HTML仍在断脚本沙箱内。Word正文和Excel工作表复用已有解析器，临时页面跟随预览句柄释放。

图片有实际解码缩略图，点击在同窗浮层放大，Esc关闭并归还焦点。模型图片/视频引用与本地预览引用指向同一份字节，不复制第二份；旧媒体目录继续可读，不迁移或自动删除历史文件。

WAV/MP4已用本地合成文件，在真实Electron内验证播放时间前进、seek、音频互斥、折叠停播及重开后等待元数据恢复进度（不自动播放）。同一资产多处展开也按实际播放元素互斥，不靠仅有资产名的单槽实现。资产库媒体协议按真实区间和64KiB背压流供给，取消或撤销停止在途流；多段/越界Range明确拒绝。

## 限额和发送边界

- 本地单文件50MiB，总持久资产1GiB；两个资产目录与在途预留同算。存量超额保留，无法核实存量时拒绝新增。
- 所有本地单件超过50MiB时本阶段**整件拒绝**，包括纯文本与日志文件：不会先收下再截断，而是要求先减小文件再附。旧版"超大纯文本仍可附、正文截断到64KiB"的通路已不再保留。
- 64KiB是**已被接受的文本送模型时的正文截断范围**（超出截断并标注），不是允许无限大文件导入的许可；本地历史副本保留完整字节。
- 图片模型通路仍5MiB，视频仍20MiB。更大但在本地50MiB内的文件仅可本地预览，不因此扩大模型输入。PDF、音频、Office引用不作为模型多模态内容发送。
- 文本类候选装入正文前先做二进制探测（前8KiB是否含NUL字节）：命中的按未知二进制降级，正文为空、不给模型，本地保留受限快照与合法归属。该探测只认NUL，不做格式识别或编码探测；真实PDF/Office/音视频仍走各自格式通路，不因容器含NUL被误拒。
- 摄取包括关闭、rename、宿主登记、结算；失败撤回本次登记和占用，不误删失败目标处外部文件。窗口在摄取期间销毁也拒绝发布。

## 真实验证与交付边界

真实write_file/edit成功事件已产生文件卡，拒绝、异常及无变化不产生假产物；当前版本刷新和原工作区归属、重启保留路径已在真应用检查。Markdown真实排版不自动加载外部图片/链接；未知/PPTX有受限副本和合法主动系统打开。系统打开检查仅替OS外设，不宣称实测了用户Word/PowerPoint安装。真实磁盘保存失败会保留输入/草稿，恢复磁盘前提后原附件可重试。

自动化用例位于tests/e2e/conversation-preview*.spec.ts，覆盖真实输入/历史/Agent产物、编辑重发、回滚/撤销和容量降级。工程检查与可复建源码的具体终态以执行回执为准，不使用测试数量代替能力或独立验收结论。

CI内真实解码仍需运行回执；仅在平台实际缺H.264解码器时明确记录该播放子项的跳过，不把资产身份、协议、音频、存档一起跳过。当前本地播放证据不替代未来目标提交的CI。

## 明确的实现边界

图片类型按宿主文件扩展名归类，真正可用性由原生解码器实读证明，不宣称只凭扩展名识别了文件内容。PDF有真实画布页面；Word/Excel是内容视图，不承诺Office像素级排版。静态HTML/Markdown不执行脚本或自动取外部资源；本阶段是单文件预览，不自动打包同目录依赖。主动系统打开沿受限句柄核真实来源，OS打开动作由测试外设记录，未启动用户真实Office程序。

### 预览URL的信任边界

预览URL是随机短期持有者能力，不是逐请求的窗口身份认证。签发时生成16字节随机handle与5分钟TTL；打开/读取/释放三个IPC入口核对请求窗口归属，销毁窗口会撤销该窗口全部handle。但URL生成后的每次资源请求（协议serve）不再从请求里认证窗口归属：已获得有效完整URL的请求者，在TTL内可能读取对应已授权字节。因此预览URL不能被外发或写入日志；随机句柄、CSP、no-store与短TTL都不是逐请求属主认证。当前生命周期与撤销机制保持不变，本阶段不为此添加新的安全机制。

### 用户附图的模型路由

当前用户附图对话统一走Agent链路：store.chatSend发起，经IPC.chatSend的唯一普通对话入口，history经materializeHistory物化媒体后进入runAgent，最终由Anthropic/OpenAI对应的Agent Provider（streamWithToolsAnthropic/streamWithToolsOpenAI）发送。非Agent的普通Provider（streamChat）仅用于反思、智能标题与提示词优化三处内部调用，不承载用户附图对话。若未来新增不经Agent-loop的用户聊天入口，须另行设计媒体契约，不能自动继承本结论。

PDF渲染复用pdfjs-dist，不依赖node-canvas。本地合成MP4只用于解码/播放回归，测试夹具自包含，CI无需ffmpeg。平台缺编码支持仅允许独立原生播放器实际解码返回明确不支持时跳过MP4单项；WAV、协议与身份仍照常执行。

图片粘贴不读取或覆盖系统剪贴板：只处理用户paste事件提供的图片文件，复用原附件IPC与同一资产事务。宿主实际解码并转成PNG；拒绝空/伪图片和超过50MiB的字节，解码画面超过16MP明确拒绝。转换后超过5MiB但在本地上限内，仅在本地预览，不生成模型图片parts。普通文本粘贴仍由浏览器处理。
