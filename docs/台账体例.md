## 一、三条硬判据（2026-10-03 立，均为本轮实测踩出来的）

### 1. 脚本自断言必须**写盘后读回产物再比**

**判据**：任何以「我已校验」自居的脚本，其校验对象必须是**从磁盘重新读回来的产物**，
不是内存里的数组、不是拷贝函数的返回值、不是「写盘成功」这个动作本身。

**为什么**：`scripts/split-ledger.cjs` 的「字节守恒」断言经证实**恒真**——
它比对的是内存数组，所以 banner 前缀剥离、尾换行、追加换行这三处字节转换**零覆盖**，
断言照样绿。恒真的尺子比没有尺子更坏：它给出的是虚假的安心。

**反例（正确形态）**：`台账整理区/tools/restore-drill-20261003.py` 对每个恢复出来的文件
**重新打开读字节**算 sha256，并做**阳性对照**（故意篡改一个文件 ⇒ 必须变红 ⇒ 还原 ⇒ 必须复归）。
阳性对照是「这条尺子不是恒真」的唯一证据，缺它就等于没测。

### 2. 台账内任何时刻只许 `date` 现取或产物文件 mtime

**判据**：写进任何台账文件的时间戳，必须是**当场现取**的系统时间，或**被描述对象的文件 mtime**。
禁止「凭记忆补一个时刻」「按上下文推一个时刻」「照抄上一份文件的时刻」。

**推论（本轮新增，最易踩）**：**更正过期读数时，替换值同样必须现取**。
把 `HEAD a11a9c0` 改成 `bab7435` 时，`bab7435` 必须当场 `git log --oneline -1` 取；
如果凭印象填，它就是**第二次造假**——而且是「更正」这个动作本身造的，更难被发现。

### 3. 插入类脚本禁把锚点自身带进插入串，插入后断言锚点唯一

**判据**：往文件里插入内容时，**插入串不得包含被用作定位的锚点本身**；
插入完成后必须**回读**并断言「该锚点/标题在全表唯一」。

**为什么**：V1 粘连（`### 1-3 …` 同一物理行出现两次）就是这样来的——
插入串自带了锚点，又拼在锚点之后。**两处必须配对**：只禁不自断言，脚本仍可能以别的形式制造重复；
只断言不禁，缺陷仍在重复被写下去的那一刻就已发生。

**实测**：改判后 5 个分块标题的条数变了，标题**必须随块边界移动**。
只重排数据行、不动标题 ⇒ 18 行落在错块（1 个 🚧 落在 ⏳ 标题下、7 个 ❌ 落在 🚧 标题下），
而当时守卫 **15/15 全绿**——守卫全条只比状态列，标题只是装饰。
⇒ 现在有两条守卫专门盯它（标题唯一 / 标题↔状态列脱钩），且都做过变异注入自测。

## 二、口径纪律

| # | 规矩 | 反例（都真发生过） |
|---|---|---|
| 1 | **摘要层与正文层同源**：头注的「主表 N 行」「状态分布」「✅ N 条，其中 ⚠️ M 条」必须与实数一致 | `### 1-1` 写「1–137，共 137 条」实为 1–136/136 条 |
| 2 | **分块标题随条数移动**：改状态即改块边界 ⇒ 标题的区间与条数必须**现算重写** | 1-1/1-2/1-3 三个标题同时过期 |
| 3 | **SID 是唯一主键，`#序号` 只是易碎坐标**：跨文档引用一律写 `#序号 · SID S0NN` 双标 | 改一格状态 → 全表重编号 → 上一轮抄的 `#74` 变 `#73` |
| 4 | **禁止裸序号引用**：裸 `#N` 在手术后会指向别的行 | 本轮实测三处旧序号配对（`#110·S131`/`#21·S026`/`#158·S920`）当场作废 |
| 5 | **复核列的 `⚠️`/`🔶` 刻意不判红**：判红会诱导把 `⚠️` 直接改成 `✅` 去消红——那是逼人伪造复核 | 头注「⚠️ 未独立复验 N 条」改为实测披露，守卫只钉「披露数 = 实数」 |
| 6 | **历史读数不回改**：过期读数走**追加更正块**，标「当时为真、现已失效」 | V2 三处过期读数、僵尸闸门三处「开工待令」 |
| 7 | **披露位不是失真**：`〔路径待核〕`、反证列里的「⚠️ 锚点路径在仓内不存在」都是**如实披露**，不许被当成断言失败清掉 | 20 条「发明架构目录」全是披露位被误判 |
| 8 | **机器判不了的，别装成机器能判**：语义真伪、决策是否落实、工作量与完成度一律属独立复核范围 | `13.5%` 与 `功能面/A-1 子集` 两把尺依赖未声明谓词，不得进判据 |

## 三、披露标记词表（可枚举 ⇒ 可证伪）

机器只校验**标记是否存在/是否带限期**，不校验标记背后的语义是否成立。

| 标记 | 含义 | 机器校验 |
|---|---|---|
| `〔路径待核〕` | 该路径**尚未确认存在**，不宣称它有效 | 必须**同格**带 `〔限期 YYYY-MM-DD〕`，且限期未过 |
| `〔仓外〕` | 路径在本仓之外（如 `D:/Tools/…`），存在性检查永远过不了 | 显式标记即免判红；无标记则判红 |
| `〔判据对象灭失〕` | 该条的判据实物（样本、目录、日志）已不存在，**不是「还没做」** | 不判红；但必须在同格写明灭失范围 |
| `〔未摊问〕` | 该条从未当面向用户摊出过，**不许写「问过日期」** | 判据⑨ 会查「待拍板语义 + 问过日期」是否成对 |
| `〔已裁分歧〕` | 两轮独立判定不一致，已按证据等级裁决 | 不判红；须同格给裁由指针（D 号） |

⚠️ **扫描器自身的坑（本轮实测三次，判据⑬/⑯）**：

1. Python `re` 的字符类里写 `[\ud83d\udea9]` 是两个**孤立代理** ⇒ 含该字符的行被静默漏检。
   字符类要用**真实字符**。
2. **JS/TS 正则无 `u` 标志时，字符类按 UTF-16 code unit 处理** ⇒ `🚧` 是代理对，
   `[🚧]` 只匹配到半个代理，`m[1]` 拿到孤立代理 ⇒ 字典查不到 → `undefined`。
   ⇒ **不要把状态图标写进正则**；捕获完整状态词再与枚举比对。
3. 「粘连检测」若按**整行**去重，就看不见「同一行内两份标题」这种形态。
   ⇒ 检测必须数**行内出现次数**。
4. 凡「零命中」结论，先做**阳性对照**（同一扫描换一个已知在场词）再采信。
5. 本机 `grep` 匹配非 BMP 字符（`🚧🔶`）静默返 0 ⇒ 状态符号计数只信 Python / `rg --no-ignore`；
   `rg` 默认吃 `.gitignore`（`PLAN/`、`NOTEBOOK/`、`DIARY/`、`台账整理区/` 全被吞）。

## 五、边界声明（机器判不了的部分，诚实列出）

- **状态语义是否真实**（「✅ 是不是真的完成」）——须逐条独立复核，不由守卫代替。
- **完成对象是哪一层**（决策 / 实现 / 验证 / 发布）——四层必须分列陈述，
  「已裁决 ≠ 已实现，有模块 ≠ 通路可用，实现 ≠ 真机验收，提交 ≠ 已发布」。
- **发布层的唯一验收口径**＝ GitHub 资产 `digest` 与本机产物 sha256 **逐位相同**；
  `CHANGELOG` 有版本标题 ≠ 有 release（本项目实测：96 个标题 vs 22 个 release）。
- **决策销账**目前**没有承载列**（D 号引用只出现在锚点/反证/摘要三列）——
  属结构欠账，见 `台账整理区/机制清单-P3-20261002.md` §三。
