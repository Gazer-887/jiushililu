# 浏览器接入（内置浏览器 + 外部浏览器自动化）

> plan60 / D-155 / D-157。最后更新：2026-10-14（plan79：原生浏览器默认开、所有 Agent 公共可用、任务授权门位与热关闭；开关与外部 MCP 分层）。

## 一、两套浏览器，两种归属

| | 内置浏览器 | 外部浏览器自动化 |
|---|---|---|
| 是什么 | 应用自带的 Chromium 视图（右抽屉「浏览器」） | 用户日常 Chrome/Edge + MCP server（如 `windows-mcp`、playwright 类） |
| 登录态 | 独立 profile，与日常浏览器**不互通** | 用户日常登录态（Agent 经 MCP 间接使用） |
| 开关 | 设置页「内置浏览器（原生）」（plan79 起；缺省开） | 设置页「浏览器操作」（外部 MCP；缺省关，显式开） |
| Agent 工具 | `browser_*`（16 个，见 §二） | `mcp__<server>__*`（由各 server 定义） |

**独立 profile 是安全边界**：Agent 因此拿不到用户日常浏览器的登录态。如需日常登录态，走外部浏览器自动化一侧。

**两个开关互不牵连**（plan79）：原生开关缺省开、只辖内置浏览器；外部 MCP 开关缺省关、语义不变。
原生开 ≠ 外部 MCP 开，反之亦然。原生开关关 = 内置 `browser_*` 整批不下发，且排队中的动作在执行点被拒。

## 二、内置浏览器工具（16 个，所有 Agent 公共可用）

**公共能力**（plan79）：不依赖角色在 `tools` 里声明——内核默认、十个内置角色、自定义角色、
被委派的子代理、聊天与一次性任务入口都能拿到（只读档除外，见下）。角色对其他工具的白名单
不受影响；`read-only` 权限档仍是硬上限，只给 `browser_navigate` 与 `browser_read_page`。

只读档可用（纯读）：`browser_navigate`、`browser_read_page`。
开开关的可写档可用（会改变远端状态）：`browser_click`、`browser_type`、`browser_hover`、
`browser_press_key`、`browser_drag`、`browser_screenshot`、`browser_snapshot`、
`browser_eval_script`、`browser_console`、`browser_network`、`browser_dialog`、
`browser_tabs`、`browser_upload`、`browser_wait`。

- 点击/输入走**真鼠标与真聚焦**（`sendInputEvent`；合成点击在 `setPointerCapture` 类页面上失灵，K22）。
- `browser_eval_script` 为高危工具：与在该页控制台粘贴执行等效，只对可信页面使用。
- 截图落盘走附件通路（配额与清理同附件）；超限/失败报人话，不静默。
- 弹窗（alert/confirm/prompt）无人处理时自动关闭并留记录，页面不会卡死。

### 任务授权门位（plan79；2026-10-14 修正批收紧边界）

- **连续操作不逐次问**：首个普通动作弹一张站点授权卡（覆盖：导航、读取、填写普通输入框、
  点击普通元素、截图），批准后同任务同站点连续执行。
- **外部作用每次问（不吃站点授权；统一事件路径规则）**：宿主沿**命中节点到根的整条事件路径**
  汇总已知危险事实——**提交控件**（button[submit]、表单内无 type 按钮、input[submit|image]）、
  **文件选择**、**任意 button**、**按钮型 input**（button/reset）、**明确 onclick**、role=button、
  **可编辑区**——任一成立即逐次确认，**不被包装层数、最近字段/链接身份或布尔短路抹掉**。
  label 另读其关联控件的路径；路径读取异常或防护性截断按未知处理（不回退叶节点称安全）。
  最近控件身份只用于描述与输入语义：普通文本框、无 onclick 的普通链接首站点授权后连续执行。
  `browser_click` 与 `browser_type`（其聚焦点击）共用同一份事实；拖拽、`browser_eval_script`、
  `browser_upload`、`browser_dialog(accept)`、`browser_press_key(Enter)` 仍逐次确认，提交卡写明表单目标。
- **计划批准闸不绕**：带计划批准的角色（approval: plan）批准前只给只读浏览器能力
  （navigate / read_page），写作用待批准后由执行阶段承担。
- 授权来源只能是**宿主导出的确认卡**；网页内容、模型自报「已获授权」都不是授权来源。
  确认卡展示真实工具名、发起者与站点（不伪装成工作区命令）。
- 拒绝、取消、超时、窗口销毁：外部作用为零。缺任务上下文或无确认服务：拒绝，不降级。
- 每次真实输入/导航/CDP 前重核开关、取消、目标与页面版本（确认等待期间关开关或人工换页 →
  旧批准不执行）。**导航加载期间检测到人工输入 → 任务暂停且不采纳新页面版本基线**（下一动作
  零输入；新任务或重新确认可继续）。每个子代理持有独立目标与授权状态（同角色并发也不共用）。
- 已发出的网络请求无法撤回；关闭开关不撤销已发生的副作用。

## 三、外部浏览器自动化怎么配

1. 在设置页 MCP 区新增 server（stdio/SSE，填命令与参数）。
2. 归类：名字或 `launchHint` 含 browser/playwright/puppeteer/chrome/edge 的，
   或工具名含 navigate_page/list_pages/select_page/take_snapshot 的，归入「浏览器操作」开关。
3. 打开「浏览器操作」开关（含桌面操控的 server 另需开「桌面操控」）。
4. 被拦的 server 会列在设置页（写明被哪个开关拦），运行日志同步记一条。

## 四、风险

- 开关开 = 该类**完整授权**：`Process`（可终止任意进程）这类也一并放行。工具描述里的风险注记是唯一的知情渠道。
- 内置浏览器的未知页面副作用按**保守确认**处理：宿主不承诺推断所有网站的按钮语义，
  未知风险停下问一次；任务授权卡覆盖一组可展示的动作，不是万能通行证。
- 页面文本与截图可能随当前模型请求发给模型服务商——不是全流程纯本地处理（设置页首次告知）。
- `browser_eval_script` 与 MCP 的 shell 类工具可执行任意代码，只对可信目标使用。
- 内置浏览器与日常浏览器登录态不互通（§一）；`shell.openExternal` 只递 URL（`file:`/`javascript:`/`data:` 已拒）。

## 五、词义分开

- 本 doc 的 CDP 通道（console/网络/dialog）操作的是**我们自己的** `WebContentsView`，
  与"连外部浏览器"的 CDP 不是一回事。
- 外部浏览器只做兼容性支持（D-157）：不做 CDP 客户端、不做扩展桥、不代起用户浏览器进程。
  将来重开需同时满足：独立 `user-data-dir`、进程生命周期自管、调试端口绑 127.0.0.1 + 随机端口 + 用完即关。
