# 判据工程与门禁

这个项目的第一性质是**学习载体**，第二性质是**公开作品**——两者都要求"能跑"之外的东西：
一条断言到底测没测到它声称的东西、一次绿到底是不是真的绿。这里记的是**判据本身的规矩**，
不是某个功能的验收步骤；功能验收在 `docs/`，踩坑过程在 `NOTEBOOK/learnings.md`。

## 五道闸与它们的顺序

一批改动合入前要过的五道：类型、静态检查、单元测试、构建、真渲染门禁。前四道能在本机跑，
第五道要真起 Electron。**顺序不是并行**：前四道是"代码成立"，第五道是"界面成立"，
跳过后者等于把 UI 断言全部当成推测。

真渲染门禁的判绿依据是它打印的那一行机器可读输出，**不是命令退出码**——细节见
[[quality-discipline#退出码是最会骗人的成功信号]]。

## 一条判据要怎样才能算存在

判据 = 把被测实现改坏之后**它当场变红**。写完就绿、改坏了还绿的，是装饰不是判据。
落地动作：交付前把修复临时退回旧形状跑一次，记下"红在哪一条"，验完还原。
这条动作的成本是几分钟，收益是"我确实测到了东西"这件事从自述变成实测。

同族的另一条：**新写的测量工具必须先在"已知答案"的数据上跑一遍**。校验器自己坏了比不校验更危险，
因为它会给出一个可以引用的假绿灯。

## 反向验证与阳性对照成对

正向验证（做完的真的做完了吗）只防虚报；**反向验证（标着未做的真的没做吗）才抓得出漏报**。
判据层面同理：一条只测"修好了"的断言，删掉修复也可能照样绿。所以每条修复判据都要配一条
**阳性对照**——测"不该被影响的那一条确实没被影响"。

写判据时还要顺手回答一句"无事发生时它输出什么"：一条永远不红的探针等于零保护，
把字段打出来却没人断言，比不打印更糟（它让人以为有人在看着）。

## 时序敏感判据不许用固定 sleep

等待条件写成"等一个可观测的静止判据 + 超时向红倒"，而不是"睡 N 毫秒再看一眼"。
`tests/unit/process-tree.test.ts` 里的 `QUIET_MS` / `DEADLINE_MS` 就是按这条改写的：
判"有没有留下孤儿进程"等的是连续零增长，等不到即判红。
固定 sleep 的问题不在于慢，在于它把**机器的排队时间**当成了被测行为的判据——
负载一压就红，而红的原因与它声称要防的东西无关。

由此还派出一条分类纪律：同一套件全量必红、单跑必过，那不是抖动，是清理或隔离出了问题。
给它贴"已知抖动"之前先数复现次数。

## 退出码是最会骗人的成功信号

"这条命令返回 0"和"这批断言全过"之间隔着好几层：包装脚本、管道、被 `execFileSync` 吞掉的子进程。
本项目实测过一次外层拿到 0 而内层全废（打印的是 `failed:355`）。
结论：**归因要归到真正做判定的那一层**，读数只认那行机器可得的输出。
同一族的反面教材是把"跳过"并进"通过"——汇总行不许写"全部通过"。

## 隔离验证进程：它不是产品

`scripts/verify-shot.cjs` 的 `assertBuildFresh` 所在的进程自建窗口、自建 IPC 桩、**不加载 `src/main`**。
所以新增一条 IPC 通道必须同批补桩，否则那边一跑就是 `No handler registered`，
继而渲染层拿到 undefined、后续探针齐红——**红得像产品坏了，其实是桩缺了**。
桩还要"真办事"：该建窗就建窗，返回空对象会让整段假红。

它也带来一类有用的副产品：**有些闸只能靠单测**。并发硬闸在那条路上整个被 stub 掉，
把上限改坏那边照样全绿——这类事实要写进测试文件的注释，否则下一个人会以为门禁罩住了它。

## 起不了真进程的场合用结构守卫

被测对象一起手就要真 Electron（或真窗口）时，退一档：读源码文本，断言"这道闸确实接在这个 handler 上"。
[[tests/unit/stream-envelope.test.ts#stripComments]] 是这类守卫的配套工具（先剥掉注释再查，
否则被注释掉的旧写法会让守卫假绿）。

要说清它的强度：结构守卫挡的是**改着改着漏掉**，不替代行为测试。
坐标失效要自己报错——守卫查的那个符号名如果被改了，它必须红，而不是"零命中 = 通过"。

## 界面判据量几何，不量存在

"DOM 里有这个节点"不等于"用户看得见"。真实渲染验证要量尺寸、算可见性、按窗口档位分档跑，
并且要承认哪些档位在真机上走不到——那类断言是**防御性保险**，登记时不许写成"复现了用户会遇到的场景"。

## 点击行为要有真指针判据

合成 `.click()` 绕过整条指针链路，"handler 写对了"与"用户点得到"因此可以一个绿一个坏。

本项目实测：刻度条加了指针捕获之后 [[src/renderer/src/views/ChatView.tsx#ChatView]] 的点击定位整个失效，
而老判据用的正是合成点击——照过。它既不产生 `pointerdown`，也不受捕获影响。
⇒ 凡"用户点一下会怎样"的断言，至少一版走 CDP `mousePressed` / `mouseReleased`，
并把 `click` 计数放进失败载荷——下次红的时候能一眼分清"没点着"还是"点了没滚"。

## 判据不许依赖界面文案

界面文案是**给用户看的**，会随语言与措辞变；判据要的是稳定坐标。所以定位与断言得分开：
定位走真 ID，断言文案才按键去 i18n 表里取。

设置分区的 `data-nav` 即为此暴露（[[src/renderer/src/views/SettingsView.tsx#SettingsView]]）。
门禁另有守卫（[[tests/unit/gate-copy-guard.test.ts]]）盯着两件事：CJS 解析层与 TS 真表必须同源；
判据里等于表内文案的裸字面量必须被**条数精确**的豁免声明 —— 多一条 = 新写硬编码，
少一条 = 那处已改好、豁免忘了删。
⚠️ 最贵的坏法不是红，是 `if (el) el.click()` 这种**找不到就跳过、返回值又被丢掉**的定位：
语言一换它静默不点，而"卡片数为 0 也算合法"的分区里，"没导航过去"与"这分区本来就空"不可分辨。
⇒ 所以中文态单跑一遍不够，**`--locale=en` 那一档必须也跑**（`npm run gate:en`）。
