# 界面语言与跨窗状态

中英双语（plan52 / G3）在代码上不复杂，复杂的是**它必须和主题走同一条路**才能不骗人。
这里记这条通路为什么长这样，以及它顺手暴露出的一个门禁盲区 —— 后者比前者更值钱。

## 语言是文档级属性，所以只能有一条通路

偏好落在 `UIPrefs.locale`（[[src/shared/splitter.ts#sanitizeLocale]] 把关，非法值回默认），
与 `theme` / `fontScale` 同一类：主进程存、改完广播、**每个窗口自己重读**。

- 为什么不存渲染端本地：两个窗口是两个渲染进程，store 各一份、互不可见。存本地必然一边新一边旧，
  那是 0.13.29 设置独立窗口时付过学费的结论。
- 为什么不做"跟随系统语言"：用户既然能在设置里选，猜的结果只会更难解释。要加也是**显式选项**。
- 回退固定中文（[[src/renderer/src/i18n.ts#ensureI18n]] 的 `fallbackLng`）而不是"当前语言"：
  缺译时宁可露中文，也不许白屏或露 key。

## 文案表用 TS 而不是 JSON

[[src/shared/i18n/zh.ts#zh]] 是权威，[[src/shared/i18n/en.ts#en]] 的类型钉在它的形状上
（[[src/shared/i18n/index.ts#Messages]]）。缺键或多键在 `npm run typecheck` 就红。
选 JSON 的代价是这类错误要等到运行时、等到某个用户点到那个页面才被发现 —— 而"哪个页面"往往正是没人测过的那个。

术语唯一译法由 [[src/shared/i18n/glossary.ts#GLOSSARY]] 兜：判据不是"表里有没有重复项"（那由构造保证，
是空转断言），而是**中文含某术语的每条文案，英文同键必须含表里的译法** —— 换词才红得起来。

## 主进程出的文，由主进程翻

用户可见文字不只来自渲染端：错误原文、确认卡、通知、智能标题。这些串由发起方按当前 locale 出文，
渲染端只显示。**否决"发 key 给界面翻"**：同一批串里有一部分根本不经过渲染端（日志、系统通知、
门禁探针），发 key 会让那部分永远是 key 或永远是中文，两套机制并存比一套丑。

日志**保持中文**。它是给我们排查用的第二份界面吗？不是 —— 混语言只会让 grep 变难。

## 桩不广播，跨窗通路就等于没被测

S1 加的端到端判据（设置窗点 English → 主窗文案变英文）第一次跑是红的：代码没错，
错在门禁的 `ui-prefs:set` 桩**只回数据不广播** `settings:changed`。

于是"收到通知就重读"这条订阅在门禁里永远不会被触发 —— 而它罩着的不只是语言：
主题、字号、字体的跨窗同步同样从未被真渲染层测过。0.13.29 就写下过"跨窗状态一律广播 + 重读"，
**规矩在，测不到**。

判据：新增或改动任何"会被广播"的状态时，先问一句**门禁里那条广播发得出来吗**。
发不出来就补桩，而不是把断言缩成"只测当前窗口"—— 后者是把这类 bug 永久留在盲区，
并且留下一条看起来有人守着的断言。
