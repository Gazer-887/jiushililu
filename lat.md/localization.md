# 界面语言与跨窗状态

中英双语（plan52 / G3）在代码上不复杂，复杂的是**它必须和主题走同一条路**才能不骗人。
这里记这条通路为什么长这样，以及它顺手暴露出的一个门禁盲区 —— 后者比前者更值钱。

## 语言是文档级属性，所以只能有一条通路

偏好落在 `UIPrefs.locale`（[[src/shared/splitter.ts#sanitizeLocale]] 把关，非法值回默认），
与 `theme` / `fontScale` 同一类：主进程存、改完广播、**每个窗口自己重读**。

- 为什么不存渲染端本地：两个窗口是两个渲染进程，store 各一份、互不可见。存本地必然一边新一边旧，
  那是 0.13.29 设置独立窗口时付过学费的结论。
- 为什么不做"跟随系统语言"：用户既然能在设置里选，猜的结果只会更难解释。要加也是**显式选项**。
- 回退固定中文（[[src/renderer/src/i18n.ts#ensureI18n]] 的 `fallbackLng`）而不是"当前语言"：
  缺译时宁可露中文，也不许白屏或露 key。

## 文案表用 TS 而不是 JSON

[[src/shared/i18n/zh.ts#zh]] 是权威，[[src/shared/i18n/en.ts#en]] 的类型钉在它的形状上
（[[src/shared/i18n/index.ts#Messages]]）。缺键或多键在 `npm run typecheck` 就红。
选 JSON 的代价是这类错误要等到运行时、等到某个用户点到那个页面才被发现 —— 而"哪个页面"往往正是没人测过的那个。

术语唯一译法由 [[src/shared/i18n/glossary.ts#GLOSSARY]] 兜：判据不是"表里有没有重复项"（那由构造保证，
是空转断言），而是**中文含某术语的每条文案，英文同键必须含表里的译法** —— 换词才红得起来。

## 主进程出的文，由主进程翻

用户可见文字不只来自渲染端：错误原文、确认卡、通知、智能标题。这些串由发起方按当前 locale 出文，
渲染端只显示。**否决"发 key 给界面翻"**：同一批串里有一部分根本不经过渲染端（日志、系统通知、
门禁探针），发 key 会让那部分永远是 key 或永远是中文，两套机制并存比一套丑。

日志**保持中文**。它是给我们排查用的第二份界面吗？不是 —— 混语言只会让 grep 变难。

## 桩不广播，跨窗通路就等于没被测

S1 加的端到端判据（设置窗点 English → 主窗文案变英文）第一次跑是红的：代码没错，
错在门禁的 `ui-prefs:set` 桩**只回数据不广播** `settings:changed`。

于是"收到通知就重读"这条订阅在门禁里永远不会被触发 —— 而它罩着的不只是语言：
主题、字号、字体的跨窗同步同样从未被真渲染层测过。0.13.29 就写下过"跨窗状态一律广播 + 重读"，
**规矩在，测不到**。

判据：新增或改动任何"会被广播"的状态时，先问一句**门禁里那条广播发得出来吗**。
发不出来就补桩，而不是把断言缩成"只测当前窗口"—— 后者是把这类 bug 永久留在盲区，
并且留下一条看起来有人守着的断言。

## 模型接入与模型事实的用户可见术语

S3-10 新增的模型接入界面带来一批用户可见词。它们与设置页既有文案一样是**渲染端中文字面量**，
不在 `zh.ts` / `en.ts` 的骨架表里；语言切换不会翻译这些串，这是当前事实，不是"已翻译"。

| 术语 | 口径 | 出现位置 |
|---|---|---|
| 供应商模板 / 协议面 | 模板是公开元数据；一条模板可有多条协议面，必须显式选面 | 模板选择器 |
| 认证方式 | 界面只给 Bearer / x-api-key 两个显式按钮；`auto` 是内部解析态，不是可点选项 | 连接表单 |
| 模型事实 | 只读展示 metadata 的解析结果，不改档案 | 模型高级设置 |
| 来源 | 用户 / 官方 / 目录 / 应用默认，四者不得混写 | 事实行 |
| 未知 | 没有任何已知来源时的唯一显示；**不是 0** | 事实行 / 价格 |
| 原生输入模态 / 原生扩展输入 | 模型原生收什么；与附件解析分开 | 模型原生输入栏 |
| 附件解析通路 | 应用能把什么解析后送进去；不证明模型原生支持 | 附件解析栏 |
| 用户覆盖 | 只覆盖上下文窗口与最大输出 Token | 已保存模型 |
| 公开 API 单价 / 聚合平台价 / 订阅套餐价 / 套餐外超额价 | 四类价格分栏，不互相换算 | 价格区 |

请求身份不单独出控件：模板选中后随连接草稿带入，最终落在条目的 `settings`。

文案口径：

- 未知态写「未知」，**不写 0、不写空价格、不写推测默认值**；真实零价写 `0`。
- 应用内回退值必须标「应用默认」，并带「应用内回退值」；不得省略来源、不得伪装成官方/目录/用户。
- 原生输入与附件解析两栏各自成句，**不写"支持 PDF 解析即原生支持 PDF"这类推导**。
- 禁用模板只显示官方原因与帮助链接，不提供可点击的生成入口。
- 观测时间显示到分钟（元数据不是秒级事实），用本地时区。
- 帮助链接一律「官方文档」，新窗口打开并带 `noreferrer noopener`。

## 速度档的用户可见术语

S3-20 的速度档带来一组新界面词。与模型接入那批一样，它们目前是**渲染端中文字面量**
（`InputConsole.tsx` / `SettingsView.tsx`），不在 `zh.ts` / `en.ts` 的骨架表里；
语言切换不会翻译这些串，这是当前事实，不是"已翻译"。

| 术语 | 口径 | 出现位置 |
|---|---|---|
| 模型默认速度 | 某个模型条目在会话未覆盖时使用的速度档 | 设置 · 模型 · 每条模型 |
| 会话覆盖 | 只对当前会话生效的速度选择；键是会话 id | 输入框速度控件 |
| 跟随模型 | 不设会话覆盖，取模型默认速度（`inherit`） | 输入框下拉 |
| 普通 | 默认速度档；不请求任何非默认服务档 | 两处下拉 / 有效值标签 |
| FAST / FAST 策略 | 速度意图为 fast；本阶段只体现为请求策略与本地并发策略值 | 两处下拉 / 有效值标签 |
| 下一轮生效 | 运行中改速度只影响下一次 run，不追改本轮 | 输入框速度控件（运行中显示） |

文案口径：

- FAST **不承诺固定加速**、不承诺价格、不承诺厂商实际档位。设置页原话是
  「会话未覆盖时使用。FAST 仅为请求策略，是否实际使用快速服务档由厂商能力声明与响应决定。」
  ——这句是承重信息，不得删改成"更快"或"已加速"。
- 输入框提示条只说明作用域与时机：「会话速度：跟随模型默认，或为本会话单独指定；只影响下一轮请求」；
  新建任务尚未创建会话时提示「暂按当前模型默认速度；会话建立后可单独覆盖」。
- 有效值标签与来源标签必须成对出现：`普通` / `FAST` 旁边标 `模型默认` 或 `会话覆盖`，
  否则用户无法判断当前值是谁给的。
- 速度文案与省 token 档位文案**分栏、分开命名**：前者是速度，后者是省 token；
  不写"FAST 更省钱"或"轻量档更快"这类跨维度推导。

## 服务档位的用户可见术语

服务档徽标与速度选择同属本地运行事实，但它们是两组词：速度回答"下一轮要什么"，徽标回答"这一轮实际发生了什么"。新增文案目前同样是**渲染端中文字面量**（[[src/renderer/src/views/ChatView.tsx]]），不在 `zh.ts` / `en.ts` 骨架表里；切换语言不会翻译它们，这是当前事实。

| 术语 | 口径 | 出现位置 |
|---|---|---|
| 请求 | 本条 assistant 消息所属 run 起点冻结的策略，不是当前设置 | 消息操作条 |
| 请求：普通 | 该 run 起点为普通档 | 消息操作条 |
| 请求：FAST | 起点为 FAST；是否真正使用优先服务档不由它证明 | 消息操作条 |
| 请求：FAST（未请求优先档） | 起点 FAST，但能力位不支持 / 未知，未向厂商发非默认档 | 消息操作条 |
| 实际 | 厂商响应的真实服务档；没有回值就是未知 | 消息操作条 |
| 实际：普通 / 优先 / 批量 | 厂商真实回值为 standard / priority / batch | 消息操作条 |
| 实际：未知 | 缺报、旧档或未观测；**不是普通、不是 0** | 消息操作条 |
| 下一轮 | 输入区速度选择的作用域：只影响后续新 run | 输入框速度控件 |

文案口径：

- 请求是意图，实际是观测；**FAST 不等于优先处理已生效，也不等于任何提速倍数**。两类徽标必须分开，不得合并成"已加速"。
- 未知态只写「未知」；不拿请求值、FAST 选择或默认值回填；真实普通回报写「普通」，不写成未知。
- 非预期但真实的容量名按有界截断原样展示，不擅自映射成普通 / 优先，也不新增供应商枚举。
- 徽标是只读文本，不暴露本地 requestId、供应商随机身份键或内部实现；不承诺价格、速度或厂商行为。
- 历史条目只读本条持久事实；切换模型 / 速度不改写历史，输入区只代表下一轮。旧档没有字段就不显示，不补「未知」。
