# 并行派发子代理

## 核心原则

**一个独立问题域，派一个子代理，让它们同时干。**

子代理带着**隔离的上下文**干活：你精确构造它需要什么，它就只看到什么——**绝不继承你会话的历史**。这既是让它聚焦，也是省下你自己的上下文留给协调工作。

## 先过两道判定

1. **失败/任务真的互不相关吗？** 修一个可能顺带修好其它的 → 相关，串行查
2. **并行之间没有共享状态吗？** 要改同一个文件、要理解全局状态、会互相干扰 → 不行，串行

通过才并行。判定错误比不并行更糟（合并冲突、互相覆盖、白干）。

## 模式

1. **按问题域分组**：这些失败各自断在什么上？（文件 A 是审批流、文件 B 是批处理、文件 C 是中止逻辑——互不影响才算独立域）
2. **为每个子代理精确构造任务书**：它要做什么（单一目标）、它需要的文件路径与事实、验收命令是什么。**只给必要的**——塞一堆无关上下文只会让它跑偏
3. **并行派发**，然后**等结果、逐一验收**（子代理自报"成功"不算数，看实际产出）
4. **汇总**：各域结果合并汇报，冲突当场解决

## 反模式

- **把一个连贯问题拆给三个代理** —— 它们互相等对方的结论，等于串行还多了协调成本
- **任务书里塞满你会话的来龙去脉** —— 子代理不需要你的历史，需要的是它的任务
- **并行期间自己也去改同一批文件** —— 你就是那个共享状态
