# 排查 CI 失败

## 第一步：分清两类失败

- **代码问题**：本地复现得出来（跑同样的测试本地也红）→ 按普通调试处理。
- **平台差异问题**：本地全绿、CI 连红 → 进入下面的平台差异清单。本项目在 ubuntu CI 上跑，本机是 Windows。

## 第二步：平台差异高频点（本项目实测踩过的）

1. **计时器粒度**：断言耗时时，Windows 与 Linux 的时钟精度不同 → 用相对比较而非绝对毫秒数。
2. **路径分隔符**：`a\b` vs `a/b` → 拼路径一律用 `node:path` 的 join/resolve，断言用 `path.sep` 或归一化后比较。
3. **大小写敏感**：Linux 文件系统大小写敏感 → require 的路径大小写必须与真实文件完全一致。
4. **排序全序**：`Array.sort` 对相同元素的顺序两平台可能不同 → 比较前先做稳定的二次排序键。

## 第三步：读日志的方法

- 找**第一个**失败步骤（后续失败常是它的连锁），不要从最后一个红叉往回猜。
- 测试失败看断言的期望值与实际值是否「同一件事的两种说法」（如 `1` vs `'1'`、`[a,b]` vs `[b,a]`）。

## 输出要求

- 给出结论：属于哪类问题、根因一句话、修法一句话。
- 修完在提交信息里注明 CI 失败的根因（下一个遇到的人不用再查一遍）。
