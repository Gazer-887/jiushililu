# 写提交信息

## 主题行

1. 格式 `type(scope): 主题`。type 按改动性质选：`feat` / `fix` / `docs` / `chore` / `refactor` / `test`。
2. 主题行写**用户可见的变化**，不写「改了哪些文件」。反例：「修改 3 个文件」；正例：「修复新会话首条消息重复」。
3. 涉及版本交付时带上版本号（如 `feat(ui): 0.13.49 —— 界面文案去批次标注`）。

## 正文

- 说明**为什么改**（动机）与**依据是什么**（实测数据 / 用户反馈 / 规范条款）。
- 关键取舍写出来：放弃了什么方案、为什么。
- 破坏性变更（构建方式 / 数据格式 / 行为默认值变化）必须显式标注。

## 硬规则

- 末尾附：`Co-Authored-By: Anan (WorkBuddy) <noreply@local>`
- 不用 emoji；不写与本次改动无关的内容。
