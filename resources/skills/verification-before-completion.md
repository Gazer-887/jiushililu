# 完成前先验证

## 铁律

**没有新鲜的验证证据，不许声称完成。**

"没验证就说做完了"不是省时间，是撒谎。违反这条的字面意思，就是违反它的精神。

## 闸门函数（声称任何"好了"之前过一遍）

1. **想**：哪条命令能证明这个说法？
2. **跑**：完整执行（必须是本条消息内的新鲜结果，"上次跑过"不算）
3. **读**：看全输出、看退出码、数失败数
4. **核**：输出能支撑说法吗？不能 → 如实报告实际状态 + 证据
5. **说**：能 → 连同证据一起说

跳过任何一步 = 撒谎，不是验证。

## 常见误区：什么不算证据

| 声称 | 需要的证据 | 不算数的 |
|---|---|---|
| 测试通过 | 测试命令输出 0 失败 | 上次的结果、"应该能过" |
| Bug 修好 | 原始症状复测通过 | 代码改了就默认好了 |
| 构建成功 | 构建命令退出码 0 | lint 过了、"日志看着没问题" |
| 需求满足 | 逐条对照需求清单 | 测试过了就默认满足 |
| 子 Agent 完成 | diff 里真有改动 | 子 Agent 自己报"成功" |

## 语气要求

验证失败时**直说**："X 没过，输出如下"，不要包装成"基本完成"。用户要的是事实，不是体面。
